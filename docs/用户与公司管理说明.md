## 字段与界面约定

### 用户

name：1–100 字符；email：原注册邮箱规则；role：1–80 字符的职位分类，可自定义，并非后台权限角色；status：active / inactive。
添加用户需要初始密码，遵循既有 8–128 位字母数字规则；本次编辑不提供密码重置。所有密码仍使用随机盐与 scrypt 保存。

当前是本机开发系统，管理接口要求有效且状态正常的账号，暂未定义管理员与普通用户的权限差别。老师确定权限矩阵后，再加入 RBAC；不要把填写 Manager 等职位理解为授予管理权限。停用或删除后端会立刻拒绝该账号已有的会话。

当前登录账号不能被删除或停用，避免误操作锁住自己。表头复选框仅全选当前页，切换搜索、角色、分页后清除选择。删除前展示数量确认；批量删除是事务操作，若任一 ID 已不存在则全部不删并提示刷新。

### 公司

- level 使用数据原值，无预设 A/B/C 或 Tier 等级分类，筛选选项来自数据库。
- annual_revenue 表示年营收，**不等于净利润**。金额按原数据的币种、单位展示，未擅自标注美元或做换汇。
- efficiency = annual_revenue / employees，由服务器计算；缺失金额、缺失员工数或员工为零时返回 null，页面显示“暂无数据”。零营收且员工大于零时比值为零。
- 颜色为当前页有效比值相对最大值的连续浅绿至深绿，表达页面内相对大小，不表示固定利润阈值或风险评级。具体阈值后续由老师确认。
- founded_year 按英文含义保存“成立年份”，supplying_since 独立保存“开始供应日期”。老师原任务将两者放在一起，语义尚需核对，不能直接用成立年份冒充供应日期。
- 员工数是非负整数，未知可留空；年营收为非负金额最多两位小数，未知可留空。编辑时可清空这些可选字段。
- 展开/收起按钮有状态和可访问名称；窄屏表格可横向滚动。

## API

以下接口均使用已有 HttpOnly 会话 Cookie，并拒绝不允许来源的浏览器写操作：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /users | 列表：search、重复 roles 参数、page（从 0 开始）、limit（1–100） |
| POST | /users | 添加用户：name、email、role、status、password |
| GET | /users/:id | 单用户详情，不含密码哈希 |
| PATCH | /users/:id | 修改 name、email、role、status |
| DELETE | /users/:id | 删除用户 |
| POST | /users/bulk-delete | body: {"ids":["uuid",…]}，最多 100 个 |
| GET | /companies | 列表：search、重复 levels 参数、page、limit |
| POST | /companies | 创建公司 |
| GET | /companies/:id | 单公司详情及计算出的 efficiency |
| PATCH | /companies/:id | 修改公司 |
| DELETE | /companies/:id | 删除公司；有关联关系返回 409 |

列表返回 items、total、page、limit 及 roles 或 levels 选项。搜索和筛选在数据库中组合执行；用户搜索仅匹配姓名，公司搜索仅匹配公司名，% 和 _ 作为文字查询。
所有写操作参数化查询。400 为格式或操作约束错误，401 为未登录/账号失效，404 为记录不存在，409 为重复值或关联冲突。

## CSV 模板与导入

模板位于 `apps/api/data/templates/`，仅包含表头，无假数据。

公司模板：

```csv
external_id,name,level,country,city,founded_year,supplying_since,annual_revenue,employees
```

external_id、name、level、country 为必需列和必填字段；其余可空。external_id 必须来自稳定的源数据编号，用来建立关系与重复导入。成立年份为四位数，日期 YYYY-MM-DD；数值不带千分位、货币符号或科学计数法；UTF-8 编码，可带 BOM。

关系模板：

```csv
supplier_external_id,customer_external_id,relationship_type
```

供应商指向客户；relationship_type 可省略，默认 supplier_of。两个编号必须已存在于公司 CSV 或数据库；自关联拒绝；同一供应商、客户及类型只保留一条。关系外键防止公司被直接误删。

从项目根目录执行（这里是用法示意路径，实际替换为收到的文件）：

```sh
npm run db:import -w apps/api -- /绝对路径/companies.csv /绝对路径/relationships.csv --dry-run
npm run db:import -w apps/api -- /绝对路径/companies.csv /绝对路径/relationships.csv
```

只导入公司时可省略关系文件。预检会执行全部校验并在最后回滚，不写入数据；正式导入为整批事务，任何错误均回滚。已有公司按 external_id 更新，关系重复跳过；CSV 没出现的既有公司不会被删除。重复列、未知列、字段错误或找不到关联编号时明确报错，等待核对映射，不静默猜测。
