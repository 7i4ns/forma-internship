# AI 核心能力第三周

> 本文记录当周历史交付边界。人工审批后的真实写入已在下一期“核心写入工具开发2”中完成。

## 交付边界

本期完成只读工具的前后端全链路联调，并建立写入工具第一周安全骨架。写入能力当前只做鉴权、DTO校验、业务规则预检与预览，不提供真实自动写入。这一边界与“写入工具默认禁止自动执行”的任务要求一致。

## 前后端联调

- 聊天输入框识别白名单 `/tool` 指令，并通过后端指令解析器调用现有工具注册中心。
- 指令示例：`/tool users.query {"search":"Alex"}`、`/tool companies.query {"country":["China"]}`、`/tool dashboard.metrics {}`。
- 用户和公司查询返回表格消息，Dashboard 返回指标卡/图表报表消息，错误以统一文本卡片展示。结果按 `resultType` 交给现有渲染器，无新建平行数据格式。
- 指令会作为用户消息与工具消息持久化，刷新后可还原结构化结果。同一会话不能由其他用户写入工具结果。
- 普通自然语言不会被猜测为写操作，`/tool users.delete {}` 等写指令不在读工具白名单内。

## 缓存与性能

- 工具注册中心统一接入用户级查询结果缓存。缓存键包含租户、用户、工具、稳定排序后的参数及数据代际，不跨用户复用。
- 用户及公司数据通过原业务 Service 新增、修改、删除后，主动使对应缓存代际失效。
- 会话上下文默认最多最近10轮、有2小时过期时间；查询结果默认10分钟。缓存失效时，会话从 PostgreSQL 恢复。
- 最终隔离环境实测：用户查询 4ms、公司查询 8ms、Dashboard 11ms；相同公司查询缓存命中在当前计时精度下为0ms，较首次少8ms。该数据为本机单次集成验收记录，不作为生产SLA或并发负载结论。

## 写入工具安全骨架

`ai-agent/write-tools` 与原只读 `tools` 物理分目录。`BaseWriteTool` 强制每个实现提供四个方法：

- `validate()`：执行参数、权限和业务规则预校验。
- `getPreview()`：生成人工可读的待变更内容，不展示密码。
- `execute()`：接口骨架已定义，但当前不会被调度为真实写入。
- `rollback()`：返回明确的预留状态，尚未实现回滚编排。

已注册的7个工具：`users.create`、`users.update`、`users.delete`、`users.batch-delete`、`companies.create`、`companies.update`、`companies.delete`。每个描述符都固定返回 `operation=write`、`autoExecute=false`、`confirmationRequired=true`。

工具类只注入 `UserService` 或 `CompanyService`，不注入 Repository、Pool，不包含业务 SQL。统一预校验服务复用现有 DTO 规则；业务 Service 新增无副作用的预检方法，真实 REST API 也调用同一方法，因此空值、格式、重复邮箱/外部编号、本人停用/删除、失效选择和公司关联冲突使用同一错误码。

`POST /ai-agent/write-tools/{name}/execute` 是安全拦截验证端点。它会先鉴权和预校验，然后由中央拦截层固定返回 `WRITE_CONFIRMATION_REQUIRED`，不调用业务写方法。未来实现不可重放的人工确认令牌前，该边界不应放开。

## 权限与审计

- 请求中的用户、租户和 IP 只由 JWT 会话及服务端映射生成，不接受工具参数注入。
- 写入预览分别需要显式 `users:write` 或 `companies:write`；职位名称不授予权限。
- 读工具执行、写工具预览和被拦截的执行都自动写入 `ai_operation_audit`，包含用户、工具、操作、参数、结果、IP、时间与耗时。
- 邮箱、电话、密码、令牌、金额与收入等字段持久化前递归脱敏。预览中不展示密码；审计不保存邮箱原文。
